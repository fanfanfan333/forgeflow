# Skill 包运行链修复

## 依据与范围

参考 [Anthropic skill-creator](https://github.com/anthropics/skills/blob/dbd4588f9e1033efb41dad4bef2f7947c8993d44/skills/skill-creator/SKILL.md)、[Claude Code Skills](https://code.claude.com/docs/en/skills)、[DeerFlow 工具策略](https://github.com/bytedance/deer-flow/blob/169002a4c995881ae046f34a540bb83b6ac828d6/backend/packages/harness/deerflow/skills/tool_policy.py) 及 [ACE v3](https://arxiv.org/abs/2510.04618v3)。固定版本、日期与具体判断见 [一手资料核对](skill-runtime-primary-sources-2026-10-17.md)。

本轮修复已有导入、按需读取和功能评测链，不引入新运行时，也不自动运行导入脚本。

## 修复

1. 包中未声明 `allowed-tools` 时不再生成 `tools=[]`；未声明继承任务权限上限，明确的空列表仍禁止工具。不会改写已持久保存的旧版本。
2. 功能评测固定完整 spec，而非只复制指令；私有试验版本绑定租户及发起人，经过正常 `skills.read`、版本/哈希校验和 `ProgressiveLoader` 读取附属文件。草案不必先发布才能被测，调用方也不能通过提交 context 构造私有版本。
3. 技能正文读取结果包含附属资源索引；四个内置包明确声明 `skills.read`，新包版本为 `1.0.1`，旧版不覆盖。
4. 已加载的正文不再要求模型重复读取；未加载正文仍按需读取。避免“重复读正文后只说下一步”的无效流程。
5. `document.inspect` 模型可见参数补上处理器已有的 `task_id`、`field`，支持使用精确任务字段配方。这是所有路径共有的工具修复，不算 Skill 独有收益。

## 真实执行证据

[合成资源读取记录](skill-resource-smoke-2026-10-17.json)：本地 `qwen3:8b`，每次随机生成校验码，校验码只存在附属文件中；成功必须有真实 `skills.read` 工具记录及正确的最终回复。初次临时测试驱动取错回复属性，未评分，单独说明而未计入成功率。

- 消除重复正文读取前：两次未实际读取目标资源，保留失败记录；运行状态虽为 completed，资源验收未通过，不能当作成功。
- 修复后：连续三次实际读取资源并正确回复；Token 分别为 1969、1971、1951。导入脚本未执行。
- 这是一个合成任务的链路检查，**没有测量业务 Skill 的额外收益**，不构成泛化、学习有效或正式发布证据。

自动化验证：核心相关测试 75 项通过；首次隔离数据库全量回归 4160 项通过、32 项跳过、1 项预期失败，另有两项旧断言失败。同步内置工具清单及“结构检查不能替代功能收益”的发布预期后，相关 20 项重新通过（包含重叠测试，不累加计数）。托管范围 Ruff、格式检查、99 个文件的类型检查及 lint 债务门禁通过。后端重启前确认没有运行任务，后端健康及前端访问均为 HTTP 200。不以脚本模型测试冒充真实模型测试。

## 保留的限制

此前业务回归两组均为 20/20、候选 Token 更多的结论未被覆盖；该候选仍不符合额外收益要求。本轮不重新包装这组已用于调试的题目为未知保留集。

只有独立对照证明质量提升，或正确率不退步且达到既有成本收益门槛，才允许新候选通过发布门禁。未全局开启可选 Skill subgraph；附属脚本的沙箱执行和可复用工具配方仍须单独验证权限、预算及恢复语义，不能因参考项目支持就直接启用。

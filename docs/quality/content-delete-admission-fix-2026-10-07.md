# 文档内删除操作被 403 拦截的修复

截图中的“帮我把文件中的;删除”属于文件内容编辑，但任务风险入口对“删除”作了全局关键词匹配，误将它升级为高风险任务。前端又从 HTTP 的 Forbidden 状态提取了“无权限”，掩盖了真实原因：要求人工审批。

修复仅识别明确指向文件/文档/文本内部内容的删除动词，并排除该动词的高风险匹配。不取消角色权限、策略和工具风险门禁；同句中的删除全部文件、清空数据库、转账、外发等动作仍要求审批。规则不会跨分句把后续破坏性删除当作文字编辑。审批错误在前端明确显示“该操作需要人工审批”，草稿继续保留。

真实 PostgreSQL/Ollama 验证：先读取新上传的两行文件，再在同一历史下发送“帮我把文件中的;删除”，HTTP 200，执行 completed，下载确认两处分号均移除、原有文字保留。运行 `b20bc406-572c-4975-bc33-c21c5cd07720`。日志：`D:/Agentxm/Multi-Agent/_audit/content-delete-live.txt`。

# 返回语句执行与附件面板修复

## 实际故障

原任务 `03ec1945-9481-4815-b3a0-6f2527eda830` 输入为“将代码优化，并且在合适位置添加返回语句”。原文件使用 CRLF。返回语句定位器生成 CRLF 匹配锚点，文本编辑器在 LF 平面执行，导致结构补充操作零匹配。后续模型重复提出函数外插入或破坏括号的操作，最终耗尽轮次。

## 修复边界

- 结构定位锚点与编辑器使用相同的换行平面；输出仍恢复原编码和换行。
- 用户明确要求添加 main 返回语句时，仅对“替换结束括号并增加 return 0”的有限操作交由作用域定位器执行。不自动修补任意损坏源码；原始编辑器拒绝函数外 return、括号不匹配的检查继续保留。
- 用户同时要求优化时，对无参数的旧式隐式 int main 入口改为 `int main(void)`，保留函数体逻辑；其他模型优化操作仍执行并验证。
- 附件选择器使用组件自行加载的样式，解决直接访问首页没有运行页面样式的问题。增加搜索、每页 12 项、滚动区域、选择数量；首页不显示删除按钮，文件管理页面及运行页仍保留原删除功能。
- 首页欢迎内容明确使用可用宽度，避免内容收缩成窄列。

## 验证

真实模型运行 `dfb36da4-0e77-4f47-bbcd-2320bffe80f4` completed / success。下载实际产物核验：`int main(void)`、原 printf、函数内 `return 0;`、CRLF 完整保留，原资源字节未修改。这不是完整 C/C++ 编译验收，也不保证所有任意代码优化需求。

后端相关 52 项测试通过，包含 CRLF / LF / CR、组合需求、原编辑器非法作用域拒绝和文档验收回归。前端全量 159 项测试通过；构建、前端 lint、项目受管 lint / 格式 / 类型检查和 lint 债务检查通过。

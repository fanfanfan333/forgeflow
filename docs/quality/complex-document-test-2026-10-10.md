# 真实复杂任务测试 2026-10-10

## 输入与测试范围

输入为用户提供的 `ForgeFlow-INC46-工程主控任务簿-v3-2026-10-03.docx`。实读 237 个正文段落、43 张表格、34 个标题；独立提取正文和表格约 48,722 字符（含测试位置标记）。上传经真实 `/resources/files` 接口，任务由 `/workspace/tasks` 执行，使用本地 qwen3:8b，无模型替身。

文档内的工程指令作为数据，本轮没有据此执行迁移、自动发布或代码任务。只操作测试产物；桌面原件 SHA256 前后相同。证据位于 `_audit/complex-document/`。

## 测试一 跨位置三项编辑

要求标题中的“工程主控任务簿”替换为“工程验收任务簿”、中部“实现了函数”替换为“实现了单个函数”、末尾“不是「读起来合理」”追加“或仅有口头说明”。其余文字、数字、样式与 43 张表格必须保留。

运行：`55e93666-4c10-4f4c-afe6-f90297199c4d`。

**失败**：中部和末尾正确；标题被整段替换为“工程验收任务簿”，删除了 `ForgeFlow INC46` 和 `v3`。段落数、段落属性和全部表格的规范化 XML 相同，原件不变，但数字不变量失败。产物可由 python-docx 重新打开，不等于视觉渲染已通过。

首个工具操作使用 DOCX 不支持的 `set_slide_title`，显式报错；随后操作产出错误标题。运行状态最终 failed/failure，助手回复却声称三项完成、所有数字保留。运行整体重试三次没有修正这一错误。

工具校验返回 data_ok=true、requirement_ok=null、numeric_changes=1。代码检查发现 `tool_handlers._doc_edit_constraints` 从模型操作推导 allowed_missing_numbers，因此整段替换导致的数字删除可能被当作允许，而没有依据原始用户要求“数字不变”。

证据：`edit-run.json`、`edit-checks.json`、`taskbook-edited.docx`。错误产物仅留作内部测试证据，不作为修复好的任务簿交付。

## 测试二 五项表格问答

要求从原文回答 T28 前置/层/里程碑、T25 迁移号/表名、Agent 三项预算、灰度阶段及最小样本/时长、阈值是否校准。独立原文答案：T12/T21/T29、L6/M3；031/artifact_version_edges；25 步/3 次/300s；5%→25%→100%、至少 30 有标签 run 且至少 24h；待校准，不得宣称达标。

运行：`9ed57943-4e70-44b9-a34b-4a92cec5313a`。

**失败**：连续六次 document.inspect，只得到段落/标题结构，没有得到目标表格内容。工具 payload 超过 4,000 字符，被包装为截断 preview。最终 max_iterations、final_answer=null；报告明确无最终答案，但运行状态却 completed/success。

代码检查发现 document.inspect 返回结构和计数，不返回正文和表格原文；ReAct 的 max_iterations 分支只发 warning，没有把耗尽轮次写入错误列表，导致外围状态判定可以标成成功。

证据：`analysis-run.json`。这不是正确回答率通过，更不能据此认定已实现长文档理解。

## 判定边界

本轮以独立原文比对为判据，不把 HTTP 200、工具执行成功、模型自述、轮次终止或产物可解压计为用户任务完成。未做 Word/LibreOffice 逐页渲染，视觉层结果为未测量。当前环境缺少 documents 插件要求的 renderer 与 LibreOffice，不以文本/结构检查替代该层。

优先整改方向：原始用户不变量约束模型编辑；提供有位置与分页的正文/表格读取；轮次耗尽和空答案不得成功；最终回复与任务状态、文件核验结果一致。以上是本轮测试发现，尚未标记为已修复。

### 核心技术决策（复用性高，值得记住）
- **Repository 抽象 + 内存/PG 双实现**：`STORAGE_BACKEND=memory|postgres`，内存实现使无 PG 环境也能跑通闭环与单测。这是本机资源受限场景下的关键手法。

### 复用性高的手法（本次验证有效）
- **改造/新建页面时用 pathless layout route** 承载全局 Shell（`createRoute({ id: 'shell', component: <AppShell><Outlet/></AppShell> })`），子路由直接拥有顶层路径 —— 比"改 layout 的 path"更干净，且便于旧路径做 redirect 兼容层。
- **前端路由改动的验证手段**：`build` 只能证明能编译；要证明"用户看到的是哪个组件"，得用**真实浏览器实访 + DOM 特征断言**（如是否存在 `.sidebar` / `.hero-stage`）。本机可用 Playwright + 系统 Chrome，无需额外安装浏览器。
- TanStack Router 的旧链接兼容：父路由 `component: () => <Outlet/>` + 子路由 `beforeLoad: () => { throw redirect({ to }) }`，再加 `legacyRedirect('/$', '/')` 兜底。

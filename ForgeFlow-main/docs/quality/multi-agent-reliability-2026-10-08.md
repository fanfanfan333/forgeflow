# Multi-agent 功能审查与可靠性整改（2026-10-08）

## 对照与方向

本轮检查智能体监督/消息分派、任务运行与取消、检查点、技能编译/来源/评估、存储隔离和相关回归。参考 [LangGraph](https://github.com/langchain-ai/langgraph)（页面显示约 42.9k stars）与 [CrewAI](https://github.com/crewAIInc/crewAI)（约 59.5k stars）；数字为本次查阅快照。

LangGraph 官方[持久化说明](https://docs.langchain.com/oss/python/langgraph/persistence)强调可恢复状态和检查点；CrewAI 官方[任务说明](https://docs.crewai.com/en/concepts/tasks)提供结构化输出、验证与有界重试。结合这些方向，保留现有 LangGraph/PostgreSQL/OpenViking 基座，优先修复有界执行、正确经验计数和可追溯来源。本轮使用这些设计原则做本地实现改进，没有安装 CrewAI 或宣称已融合它的全部运行时。

## 已修复

| 实际缺陷 | 程序改动 | 验证 |
|---|---|---|
| A2A 内存队列满 100 条后 send 一直等待，可能卡住图节点 | 满队列立即抛出可捕获的 QueueFull，保持队列上限，由现有 best-effort 调度记录失败 | 满队列条件下分派及时返回，不虚增计数 |
| 智能体发现操作位于异常保护之外 | 将发现放进保护范围 | 模拟发现失败，调度返回 None，图继续处理 |
| 消息未入队已更新运行计数 | 入队调用成功后才更新 | 拒绝入队时计数保持不变；该计数仍是派发统计，不是完成回执 |
| 手动经验编号重复会凑够最小样本数；相似检索也可能重复 | 手动按编号去重，自动检索去重 | 一条经验重复 20 次仍不足 |
| 同一批经验不断生成重复候选 | 复用同租户最近 200 项中的 draft/evaluating 同源候选；同进程同租户编译串行并清理空闲锁 | 四个并发编译返回一个候选；实际 API 三次并发数量 7→7 |
| 手动多经验只写入第一条来源关联 | 对全部来源写入关联，手动来源相似度实际计算，严格校验关联长度 | 三条真实经验对应三条关联 |
| 同步模型调用阻塞事件循环，草稿生成没有截止时间 | 移至线程执行，默认 30 秒 deadline，超时使用已有规则草稿 | 阻塞模型情况下事件循环继续执行，并按 deadline 返回规则草稿 |
| 删除“最近活动”后旧测试仍要求其 DOM 和函数存在 | 仅退役用户明确删除的两个控件编号，状态一致性约束迁移到现有历史列表 | 相关 57 项通过，保留其他基线和负向检测 |

新增配置：`SKILL_CANDIDATE_DRAFT_TIMEOUT_SECONDS`，默认 30，允许 0.1–300 秒。规则草稿仍需原有评估/发布门禁，不会超时后自动发布。线程里的第三方调用可能在响应超时后自行完成；它不进行候选保存，故不会晚到后再写第二份候选。

## 框架结论与边界

项目具备真实 LangGraph 节点路由、工具执行、权限/审批、审计、持久化检查点和独立上下文服务，值得在此基础上改进。通用聊天路径仍主要是 ReAct 工具执行，不应把每次普通问答都称为多个独立智能体协作。A2A 分派目前主要承担审计/注册表观测，不能以一次消息入队证明远端智能体完成了任务。部分命名业务工作流仍是模板。

本轮候选锁限单个工作进程，跨进程/跨节点防重仍需数据库唯一约束或分布式任务治理；候选查重范围是最近 200 项。现有单工作进程 OpenViking 文件队列亦不等于多节点高可用。业务端幂等、真实外部连接器验收、模型事实提炼质量与高可用部署应分别验证，不以项目 stars 或本地测试通过推断企业级完成。

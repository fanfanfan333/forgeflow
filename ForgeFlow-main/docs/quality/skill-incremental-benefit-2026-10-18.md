# 从重复指令到可复用的只读准备步骤

本轮处理的是 Skill 的实际增益，不修改已有 10% Token 节省门槛，不降低无 Skill 基线能力，也不缓存测试答案。

## 设计依据

- [Anthropic skill-creator 固定版本](https://github.com/anthropics/skills/blob/dbd4588f9e1033efb41dad4bef2f7947c8993d44/skills/skill-creator/SKILL.md)：从执行轨迹整理可复用操作，比较无技能／候选的真实结果，而非只看指令是否完整。
- [Claude Code Skills](https://code.claude.com/docs/en/skills)：按需指令与支持资源；复用成功操作配方，减少每次重新发现步骤。
- [SkillRevise v4](https://arxiv.org/abs/2606.01139v4)，2026-09-03：根据实际执行证据诊断、局部修订并重新执行候选。这里只采用方法，不引用外部成绩作为本项目效果。
- [SkillsBench v4](https://arxiv.org/abs/2602.12670v4)，2026-06-14：相同任务、相同模型框架、有／无 Skill 成对评测；强调聚焦技能，不叠加大而全的上下文。

## 实现

复用现有 `procedure` 和 ReAct 工具循环。只有显式声明 `execution: prepare` 的一步可以先于模型执行；仍经过同一套工具白名单、父任务权限、RBAC、HITL、参数注入、共享预算、取消、检查点和工具证据记录。模型继续负责读取结果、必要的补读和最终回答。

允许 `document.inspect`、`textfile.inspect`、`sheet.inspect`；不允许写操作、网络请求或脚本。参数只允许原始任务查询、受限文档页大小，以及从任务文本中唯一编号绑定的精确字段选择。不允许指定路径、租户或测试答案。多个编号或无编号时不猜测，回到正常模型规划；一个任务最多一条准备调用。

`skill_preparation` 和每轮 `origin` 记录准备步骤的真实来源；模型调用次数只统计实际模型调用，不将确定性操作伪装成模型调用。已加载技能版本与内容哈希写入检查点，恢复时版本发生变化则拒绝继续。功能评测新增异常类型链，避免只有空错误字符串而无法诊断。

## 可复用定义示例

这是单个工程任务目标字段审阅的定义片段，可由现有版本／候选 spec 接口保存。不是自动发布授权；普通 `SKILL.md` 正文也不会自动变为平台可执行代码。

```json
{
  "instructions": "只读审阅。先使用本任务已有原文观测；编号或字段不符、原文缺失或字段截断时继续精确读取。资料不足明确说明，不猜测，不修改文件。",
  "tools": ["document.inspect", "evidence.read", "report.render"],
  "procedure": [{
    "purpose": "复用任务目标字段的精确读取",
    "execution": "prepare",
    "tool": "document.inspect",
    "args": {"task_id": "$task_id", "field": "目标", "limit": 1}
  }]
}
```

适用范围是单文档、单个任务目标字段审阅。复杂跨文档任务、代码修复和文档清洗不能据此宣称已经获得相同收益。普通旧流程保持原样；没有准备声明的 Skill 不会被自动转换。

## 试验保留原则

20 条已获用户确认的业务案例来自同一个工程任务簿，已经用于诊断，因此本轮定位为业务回归，不能称为未知来源保留集或跨文档泛化证明。源文件、断言和答案不变，使用同一 Ollama 模型与参数；候选版本与输入哈希固定。

首个试跑减少了模型调用，但总 Token 节省不足门槛。接着的一条记录分页方案把“还有其他记录”混同为“当前字段不完整”，增加了调用，已停止并保留结果。精确字段版的首次完整对照出现一段两组均未测量的执行中断，也停止并保留；根因尚未确证，不归因于 Skill，也不删除失败行或拼接成功子集。之后在离线回归结束后新建完整独立运行，补充异常类型诊断。

## 完整运行结果

最终独立运行完成 40 次真实执行：[公开统计](skill-benefit-summary-2026-10-18.json)。两组使用同一 `qwen3:8b` 摘要、temperature=0、num_ctx=8192、think=false，输入文件和批准的验收断言未改变。

| 指标 | 无 Skill | 修订 Skill |
| --- | ---: | ---: |
| 通过 | 20/20 | 20/20 |
| Token | 63,955 | 44,904 |
| 实际模型调用 | 40 | 21 |
| 实际工具调用（包含报告） | 40 | 41 |
| 累计执行秒数 | 259.474 | 190.405 |

记录 Token 减少 **29.8%**，没有质量退步或错误完成，按原有门禁得到 `functional=pass`、`benefit.positive=true`。耗时仅为本机本轮记录，不解释为稳定延迟收益或 SLA。指令和准备步骤的各自贡献未单独消融；只证明这份完整 Skill 定义在当前配对回归中的收益。

额外两份合成 DOCX 揭示了共同读取器的缺陷：普通样式的独立任务编号未关联后面的表格。修复后，使用相同文件，两组共四次真实执行均通过。最初探针还漏写报告格式；补齐显式 Markdown 验收后原始回答仍然失败，因此没有靠校准将失败变绿。失败记录与重新执行的记录分别保留。

共享读取器修复发生在完整模型对照之后，因此另对该轮 **41 次实际业务读取**回放修复前后函数，输出全部一致；未重跑这 40 次模型调用，也未重写原评测的运行时哈希。公开统计保留两份代码哈希及回放范围。共享读取器修复不算 Skill 独有收益。

自动化验证：此前隔离数据库广泛回归 4,179 项通过、16 跳过、1 预期失败；最终相关核心回归及新增普通段落编号用例通过，托管 lint、格式、99 文件类型检查和 lint 债务门禁通过。计数存在重叠，不相加。所有来源文档与答案留在本地，公开统计不包含业务原文。

该候选保持草稿，未自动发布。结论限于单文档已知回归与两份合成冒烟；尚无多次重复统计、独立人工跨文档保留集或所有 Skill 均有收益的证据。先前执行中断根因未确证，独立重测成功不表示该故障已被永久消除。

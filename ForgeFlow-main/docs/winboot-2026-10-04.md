## 1. 根因

**根因层不是 psycopg，而是 uvicorn 自己的 loop factory。**

本机实际安装版本：**uvicorn 0.53.0**。`uvicorn/loops/asyncio.py`：

```python
def asyncio_loop_factory(use_subprocess: bool = False):
    if sys.platform == "win32" and not use_subprocess:
        return asyncio.ProactorEventLoop   # ← reload/workers 关时强制 Proactor
    return asyncio.SelectorEventLoop
```

而 `uvicorn/server.py::Server.run` 是：

```python
asyncio_run(self.serve(...), loop_factory=self.config.get_loop_factory())
```

⇒ **它走自己的 factory，从不读 `asyncio.set_event_loop_policy`**。

因此：**文档 §2 的处方（只在启动入口设 `WindowsSelectorEventLoopPolicy`）对本机 uvicorn 版本实证无效**。实测（`_boot_probe2_result.txt`）：

| 配置（进程内**已设** Selector policy） | `use_subprocess` | `get_loop_factory()` 返回 |
|---|---|---|
| `Config(reload=False)` | `False` | **`ProactorEventLoop`** |
| `Config(reload=True)` | `True` | `_WindowsSelectorEventLoop` |
| `Config(workers=2)` | `True` | `_WindowsSelectorEventLoop` |
| `Config(loop="none")` | `False` | `None`（⇒ 交还 policy） |

链路：

```
python -m forgeflow.bootstrap
   ↓
Python 3.13.14 · uvicorn 0.53.0
   ↓
★ Config.get_loop_factory()      ← 根因层（reload 关 ⇒ Proactor）
   ↓
asyncio_run(serve(), loop_factory=...)   ← 绕过 event loop policy
   ↓
FastAPI lifespan
   ↓
STORAGE_BACKEND=postgres → asyncpg.create_pool()【主池】
                         + AsyncPostgresSaver(psycopg3)【LangGraph 检查点】← 抛 InterfaceError
   ↓
PostgreSQL :5433（docker forgeflow-main-postgres-1, healthy）
```

抛错原文（故意不修时的复现，见 §11-A）：

```
psycopg.InterfaceError: Psycopg cannot use the 'ProactorEventLoop' to run in async mode.
Please use a compatible event loop, for instance by running
'asyncio.run(..., loop_factory=asyncio.SelectorEventLoop(selectors.SelectSelector()))'
ERROR:    Application startup failed. Exiting.
```

### 与文档原文的 3 处事实偏差（已纠偏，非擅自改动）

1. **§2 的「只设 policy」不足以修 `reload=False`** —— 这是要修的那个场景本身。故采用用户 Q1 裁定方案 **A**：policy **与** `get_loop_factory` 覆写双保险。
2. **§4 审计对象写作 `psycopg_pool` / `AsyncConnectionPool`** —— 全库检索确认**不存在** `AsyncConnectionPool`；主池是 **asyncpg**（`forgeflow/database.py`），psycopg3 只服务 LangGraph 检查点（`forgeflow/graph/checkpointer.py`）。生命周期因此审的是**两条**：asyncpg 池 + psycopg 检查点 CM。
3. **§8/§9 建议落 `backend/bootstrap/` 或复用 `infrastructure/runtime`** —— 但 `forgeflow/runtime/` 是 **agent 运行时**（orchestrator/react），放进程引导会污染业务语义；故新建 `forgeflow/bootstrap/`，职责单一。

**安全性前提（已核实）**：`forgeflow/` 内已无 `asyncio.create_subprocess_*` 残留（INC26 Option-A 已解耦），故全局切 Selector 无副作用。

## 3. 每个文件修改了什么

### 3.1 `forgeflow/bootstrap/runtime.py`（新增，核心）

Windows Runtime Guard，职责只有三件事：**检测平台 → 设置 Selector 循环 → 输出 diagnostic**。不含任何业务逻辑。

- `install_windows_selector_policy()`：非 win32 原样返回；win32 下设 `WindowsSelectorEventLoopPolicy`。**覆盖非 uvicorn 的 asyncio 入口**（测试进程、工具脚本）。
- `selector_loop_factory()`：`asyncio.SelectorEventLoop(selectors.SelectSelector())`。
- **模块级** `ForgeFlowConfig(uvicorn.Config)`：覆写 `get_loop_factory()`——win32 返回 Selector factory，POSIX 交还 `super()`。
  > ⚠️ 必须是**模块级**类：uvicorn `reload=True` 走 `ChangeReload` **把 Config pickle 进子进程**，函数内定义的类不可 pickle，会导致 reload 子进程里覆写丢失。这一条已实测 pickle 往返验证（见 §19）。
- `run_api_server(app, host, port, reload=..., ...)`：唯一后端启动入口。内部走 `uvicorn.Server(ForgeFlowConfig(...))` / reload 时由 supervisor 把 Config（含覆写）带进子进程。**默认 `reload=False`**，另提供 `--reload`。
- `log_boot_diagnostics()`：在**运行中的 loop 内**输出 `[BOOT]` 八行；若 postgres 档落到非 Selector 循环，额外打一条明显的 MISCONFIG 行。
- `__all__` 导出 `run_api_server` / `log_boot_diagnostics` / `get_config_class` 等。

### 3.2 `forgeflow/bootstrap/__init__.py`（新增）

暴露 `run_api_server`、`log_boot_diagnostics`；惰性载入 uvicorn，使只想要 policy 的调用方（`tests`、工具）不必拉起整个 server。

### 3.3 `forgeflow/bootstrap/__main__.py`（新增）

CLI：`python -m forgeflow.bootstrap [--host --port --reload --log-level --reload-dir]`，默认 `reload=False`。

### 3.4 `forgeflow/api/main.py`（修改，+30 / −2）

三处，全部集中在 `lifespan()`，无业务逻辑变更：

1. **启动可观测性**：`lifespan` 首行调用 `log_boot_diagnostics()` —— 从运行中的 loop 内部采样，因此 `event_loop` 是**服务器真正拿到的**循环类，不是启动前的猜测。新增 import 一行。
2. **DB 生命周期显式日志**（postgres 分支）：
   ```python
   logger.info("[DB] initializing PostgreSQL pool")
   try:
       app.state.pool = await init_pool()
   except Exception as exc:
       logger.error("[DB] PostgreSQL pool initialization FAILED: %s: %s",
                    type(exc).__name__, exc)
       raise
   logger.info("[DB] PostgreSQL pool ready")
   ```
   **故意没有** `try: postgres except: memory` 回落 —— postgres 档必须真实初始化，失败必须由 uvicorn 终止启动。
3. **shutdown 只在真的有池时打 `[DB] … closed`**（修一个诚实性缺陷：原先 memory 档也会打「pool closed」，而它从未开过池）。

### 3.5 `tests/realstack/test_realstack_t5_win_boot.py`（新增）
